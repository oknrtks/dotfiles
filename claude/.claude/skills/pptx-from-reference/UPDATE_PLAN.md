# pptx-from-reference スキル改善計画

**作成日**: 2026-04-20
**問題**: LLMがPhase 4でテンプレート検証時に、元の具体的なデータが残っているスライドを「問題ない」と誤判断した

---

## 問題の概要

### 発生した事象

スライド3のテンプレート化において:
- タイトル: 「テンプレートスライド3」に変更済み ✓
- リード文: Placeholder化済み ✓
- **左カラム本文**: 元の具体的な進捗報告がそのまま残存 ✗
- **右カラム表**: 元のスケジュール表（日付・内容）がそのまま残存 ✗

LLMはこれを「問題ない」と判断し、「保持された要素」として肯定的に評価してしまった。

### 根本原因

1. **Phase 4の検証項目に「具体的データの残存確認」がない**
2. **「保持」の意味が曖昧**（書式を保持 vs データを保持）
3. **Phase 3に本文・表の処理方法が明示されていない**
4. **「テンプレート」の定義が不明確**
5. **検証方法が具体的でない**（どう確認するか不明）

---

## 是正策

### 1. Phase 4の検証項目を改訂（最優先）

**現在の問題点:**
- 検証項目に「具体的データが残っていないか」という最重要項目がない
- 「保持」を肯定的な言葉として使っているため、データ残存を良いことと誤認

**改訂内容:**

SKILL.md 377-387行目を以下に置換:

```markdown
### 4-2. 元スライドとの比較確認（必須）

各テンプレートスライドについて、以下の検証を**必ず実施**する:

#### ✓ テンプレート化の完了確認（最優先）

**【重要】以下を確認してから、他の項目に進むこと:**

- [ ] **具体的なデータ（固有名詞・日付・数値・実際の文章）が残っていないか**
  - タイトル: 「テンプレートスライドN」になっているか？
  - 本文: Placeholderテキスト（【本文】...）になっているか、または削除されているか？
  - 表・グラフ: 削除されて代替矩形になっているか、または元のデータが残っていないか？
  - リード文: Placeholderテキストになっているか、または削除されているか？

**確認方法:**
1. 元スライドと並べて画像を表示
2. 元スライドの具体的な文言（例: 「①日本オラクル社との連携品質向上」「10/23のCSS月例で議論実施」）がテンプレートに残っていないか目視確認
3. 表の日付・数値・内容がそのまま残っていないか確認

**判断基準:**
- ✓ 良好: すべての具体的データがPlaceholderまたは代替矩形に置換されている
- ✗ NG: 元の文言・データが1つでも残っている → **即座に修正が必要**

#### ✓ コードによる検証（必須）

視覚確認だけでは不十分なため、以下のコードで全shapeのテキストを確認:

```python
uv run python - <<'EOF'
from pptx import Presentation
prs = Presentation('template_<input>.pptx')
for slide_idx, slide in enumerate(prs.slides):
    print(f"\n=== Slide {slide_idx + 1} ===")
    for shape in slide.shapes:
        if shape.has_text_frame and shape.text.strip():
            text = shape.text[:80].replace('\n', ' ')
            print(f"id={shape.shape_id:4d} text={text!r}")
EOF
```

**判断基準:**
- ✓ 良好: すべてのテキストが「テンプレートスライドN」「【...】」形式、または空
- ✗ NG: 元の具体的な文言（固有名詞、日付、詳細な説明文等）が出力される → 修正必要

**元スライドと比較して、同じ文言が残っていないか確認すること。**

#### ✓ レイアウト・書式の保持確認

- [ ] タイトル・リード文・本文のPlaceholderが適切な位置に表示されているか
- [ ] フォント・色・サイズ・背景色が元スライドから継承されているか
- [ ] 図領域の代替長方形が適切な位置・サイズか
- [ ] Placeholderテキストがshapeからはみ出していないか（特に大フォントshape）

#### ✓ 不要要素の削除確認

- [ ] 削除すべきshape（具体的なデータを含む図・グラフ・表）が残っていないか
- [ ] 意図しない要素の欠落・重複がないか
```

**変更理由:**
- 「具体的データの残存確認」を最優先項目として明記
- 確認方法を具体化（目視+コード検証の両方を必須化）
- 判断基準を明確化（NG基準を明示）

### 2. Phase 3に「本文・表の処理」セクションを追加

**現在の問題点:**
- Phase 3にタイトル・リード文・図の処理は書かれているが、本文・表の処理が明示されていない
- そのため、LLMは「表は保持すればよい」と誤解してしまった

**改訂内容:**

SKILL.md 364行目の後に以下のセクションを挿入:

```markdown
### 3-5. 本文・表・グラフのPlaceholder化

**重要:** タイトル・リード文だけでなく、**すべての具体的なデータ（本文・表・グラフ）もPlaceholder化または削除する必要がある**。

#### 本文の処理

本文shapeに具体的な内容が記載されている場合、以下のいずれかの方法で処理する:

**選択肢1: Placeholder化**（シンプルなテキストの場合）

```python
shape = find_shape_by_id(slide, body_id)
if shape:
    placeholder_text = '''【本文】詳細説明・根拠・データなどを記載
・文字色: #XXXXXX / サイズ: XXpt
・強調方法: 色(#XXXXXX) / Bold / Italic / フォント拡大
・文体: ですます調 / 箇条書き多用 等
・構成: 1ペイン / 2ペイン(左:図 右:説明) 等
・図: あり / なし
・表: あり / なし'''
    set_text_preserve_style(shape, placeholder_text)
```

**選択肢2: 削除して代替矩形**（複雑な箇条書き・複数カラム等の場合）

```python
shape = find_shape_by_id(slide, body_id)
if shape:
    coords = (shape.left, shape.top, shape.width, shape.height)
    remove_shape_by_id(slide, body_id)
    add_placeholder_rect(slide, *coords, '【本文領域】ここに本文を記載')
```

**選択基準:**
- シンプルなテキストボックス → Placeholder化
- 複雑な構造（複数段落、複雑な箇条書き、レイアウトが崩れる可能性がある場合） → 削除して代替矩形

#### 表・グラフの処理

**表・グラフは必ず削除して代替矩形に置換する**（テキスト置換では処理できないため）:

```python
# 表のshapeを特定（Phase 2で特定したshape_idを使用）
table_shape = find_shape_by_id(slide, table_id)
if table_shape:
    # 座標を記録
    coords = (table_shape.left, table_shape.top, table_shape.width, table_shape.height)
    # 表を削除
    remove_shape_by_id(slide, table_id)
    # 代替矩形を配置
    add_placeholder_rect(
        slide, *coords,
        '【表領域】この箇所にスケジュール表・データ表を配置する\n（元スライドではXXX表が使用されていた）'
    )
```

グラフも同様に処理:

```python
# グラフのshapeを特定
chart_shape = find_shape_by_id(slide, chart_id)
if chart_shape:
    coords = (chart_shape.left, chart_shape.top, chart_shape.width, chart_shape.height)
    remove_shape_by_id(slide, chart_id)
    add_placeholder_rect(
        slide, *coords,
        '【グラフ領域】この箇所にグラフ・チャートを配置する\n（元スライドではXXXグラフが使用されていた）'
    )
```

#### 判断基準

- 元スライドに具体的なデータ（文章、表、グラフ、日付、固有名詞等）がある → **必ずPlaceholder化または削除**
- 装飾・枠線・背景色・レイアウト構造のみ → 保持してOK

#### 処理の優先順位

1. **最優先**: 具体的なデータの削除・Placeholder化
2. **次優先**: レイアウト・書式の保持

**データが残っているテンプレートは再利用不可能なため、不完全なテンプレートとなる。**
```

**変更理由:**
- 本文・表の処理方法を明示
- 「必ずPlaceholder化または削除」と強い表現で要求
- 選択肢と判断基準を明確化

### 3. 「テンプレート」の定義を明確化

**現在の問題点:**
- 「テンプレート」という言葉が使われているが、明確な定義がない
- そのため、「元のデータが残っていてもテンプレート」と誤解される

**改訂内容:**

SKILL.md 6-8行目を以下に置換:

```markdown
# pptx-from-reference スキル

与えられたPPTXを参照資料として、そのデザイン・レイアウト・文体を解析し、再利用可能なテンプレートPPTXを生成する。

## テンプレートの定義

**テンプレート = 具体的なデータを含まず、レイアウト・書式のみを保持した「型」**

- **保持するもの**: レイアウト構造・書式（フォント・色・サイズ・背景色）・装飾・配色・余白・配置
- **削除またはPlaceholder化するもの**: 具体的なデータ（固有名詞・日付・数値・実際の文章・表の内容・グラフのデータ）

**判断基準:**
- ✓ テンプレート: 新しいコンテンツを入れるだけで別の資料として使える
- ✗ 不完全: 元の具体的データが残っており、削除・修正しないと使えない

**例:**
- ✓ 良い: タイトル「【タイトル】ここにタイトルを記載」、本文「【本文】詳細説明を記載」
- ✗ 悪い: タイトル「基幹システム1部開発3G報告」、本文「L mtg.について日本での再開が11/3週中頃...」
```

**変更理由:**
- テンプレートの定義を明確化
- 保持するもの・削除するものを明示
- 良い例・悪い例で判断基準を具体化

### 4. Phase 2の選定基準を明確化

**現在の問題点:**
- 「汎用性が高く特定データに依存しない構造」と書かれているが、「構造」と「データ」の区別が不明確
- 選定後にデータを削除する必要があることが明示されていない

**改訂内容:**

SKILL.md 119-132行目を以下に改訂:

```markdown
### 2-2. 参照スライドの選定

**対話モード:** 全スライドの概要を報告し、**選定案を提示して利用者の明示的な承認を得てから**次のフェーズに進む。承認なしに自動進行してはならない。

**委任・非対話モード:** 利用者から「LLMが考えてくれ」「適当に選べ」「適切に選べ」等の回答、または確認できない場合は以下の基準で自動選定（最大5点）:
- 汎用性が高く特定データ・固有名詞に依存しない**構造**（注: データではなく構造を選定）
- タイトル・リード文・本文などの要素が揃っている
- 類似レイアウトは代表1点のみ
- 表紙・中表紙・背表紙は存在すれば別途記録

**重要な注意事項:**
- 選定の目的は「レイアウト構造」を取得することであり、「データ」を取得することではない
- 選定したスライドに具体的なデータ（進捗報告の詳細、日付、固有名詞、表の内容等）が含まれている場合、Phase 3でそれらを**必ずPlaceholder化または削除**する必要がある
- 「このスライドはデータが少ないから選ぶ」のではなく、「このレイアウト構造が有用だから選ぶ（データはPhase 3で削除する）」という判断をすること

**表紙・中表紙の取り扱い:** タイトル・サブタイトルなどのshapeを特定し、`テンプレートスライド` と同様にPlaceholderテキスト（例: `【表紙タイトル】ここにタイトルを記載`）に置き換える。

**背表紙の取り扱い:** テンプレートに含めるが、一切手を加えない（画像・ロゴ主体のため）。
```

**変更理由:**
- 「構造」と「データ」の区別を明確化
- 選定後にデータを削除する必要があることを明記
- 選定の判断基準を補足

SKILL.md 388-398行目を以下に改訂:

```markdown
### 4-3. 修正ループ

**少なくとも1回は修正→再確認サイクルを実施する**（問題ゼロに見えても必ず1周行う）。

問題が見つかった場合:
1. `_work/build_template.py` を修正
2. 再実行してテンプレートを再生成
3. 4-2 の確認を繰り返す
4. 問題がなくなるまで継続

**特に注意すべき問題:**
- **具体的なデータが残っている**: 最優先で修正（本文・表・グラフ等）

**最終確認:** すべての修正ループが完了した後、**全スライドを改めて通しで確認する**（修正対象以外のスライドに意図しない影響が出ていないか）。

**最終確認時のチェックリスト:**
- [ ] すべてのスライドで具体的なデータが残っていないか（コード検証を実施）
- [ ] すべてのスライドでレイアウト・書式が保持されているか
- [ ] 不要なshapeが残っていないか、必要なshapeが欠落していないか
```

**変更理由:**
- 「特に注意すべき問題」として具体的なデータ残存を最優先に明記
- 最終確認時のチェックリストを追加

## 期待される効果

### 改訂前の問題

LLMは以下のように判断していた:
- 「タイトルが変わった」✓
- 「リード文がPlaceholderになった」✓
- 「レイアウトが崩れていない」✓
- **「表・本文が保持されている」✓** ← 誤判断

→ 「問題ない」と結論

### 改訂後の期待

LLMは以下のように判断する:
1. **最優先**: 具体的なデータが残っていないか確認
   - 元スライドの文言「①日本オラクル社との...」がテンプレートに残っている ✗
   - **即座に「問題あり」と判断**
2. コード検証で全shapeのテキストを確認
   - 元の具体的な文言が出力される ✗
   - **「修正が必要」と判断**
3. build_template.pyを修正し、表・本文をPlaceholder化または削除
4. 再確認して問題がなくなるまでループ

### 根本的な改善

- 「データ残存 = NG」という判断基準が明確化される
- 検証方法が具体化される（目視+コード検証）
- Phase 3で本文・表の処理方法が明示される
- 「テンプレート」の定義が明確化され、誤解が防止される

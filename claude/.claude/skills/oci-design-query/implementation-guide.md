# 実装ガイド

## Step 1: マルチヘッダー結合ツール実装

### 目的

Excelからカラム名を正しく抽出

### 処理内容

1. Excelファイルを読み込んで最初の数行を確認
2. 「#」を含む行をデータ開始行と判定
3. その手前までをヘッダー行として結合処理
4. Unnamedカラムを前行の値で埋める
5. 結合されたカラム名リストを出力

### 検証

現行10ファイルで正しく結合できるか確認

## Step 2: インデックス構築ツール実装

### 目的

Excelからインデックス（ポインタ情報のみ）を生成

### 処理内容

1. DataFrameをパースして各行を走査
2. 主キー（#カラム）を検出
3. by_resourceインデックスを構築：{主キー値: {sheet, row}}
4. by_column_valuesインデックスを構築：{カラム名: {値: [(リソースタイプ, 主キー)]}}
5. ファイルのmtimeを記録

### 重要

インデックスにはデータを含めない、ポインタ情報のみ

## Step 3: 問い合わせクラス実装

### 目的

インデックスとDataFrameを使って高速に問い合わせ応答

### 処理内容

1. テナント指定時にタイムスタンプチェック
2. 更新があれば差分更新
3. インデックスで位置を特定
4. DataFrameから実際のデータを取得
5. 結果を整形して返す

### メソッド

- `get_row(tenant_id, resource_type, primary_key)`: 特定行の全属性
- `get_column_values(tenant_id, column_name)`: 列の全設定値
- `search(tenant_id, filters)`: 条件検索
- `search_across_tenants(filters)`: テナント横断検索

## Step 4: 更新検知と差分更新実装

### 目的

ファイル更新を自動検知して最小限の再ロード

### 処理内容

1. テナントアクセス時にmtime比較
2. 更新ファイルのリストアップ
3. 更新ファイルのみ再パース
4. 該当シートのDataFrameを差し替え
5. 該当シートのインデックスのみ再構築

## Step 5: LLMインターフェース実装

### 目的

LLMから使いやすいAPIを提供

### 処理内容

1. 自然な問い合わせをインデックス検索に変換
2. 結果をLLMコンテキスト用にフォーマット
3. エラーハンドリング

### 使用例

```python
inventory = OCIInventory(Path("/tenants"))

# 列単位: 「全VCNの環境設定値を教えて」
env_values = inventory.get_column_values("ocicloudjapanuser1", "環境")
# {"ルート": ["VCN:ai-vcn", ...]}

# 行単位: 「ai-vcnの全設定を教えて」
ai_vcn = inventory.get_row("ocicloudjapanuser1", "VCN", "ai-vcn")
# {"名前": "ai-vcn", "コンパートメント名": "ai-cmp", ...}

# 横断: 「全テナントのsandboxコンパートメントを教えて」
results = inventory.search_across_tenants({"compartment": "sandbox"})
# {"tenant1": [...], "tenant2": [...]}
```

## 検証

### 機能テスト

1. **マルチヘッダー結合**: 全ファイルで正しくカラム名を結合できる
2. **インデックス構築**: インデックスが正しく構築され、データを含まない
3. **行単位取得**: `get_row()` で正しく行データを取得
4. **列単位取得**: `get_column_values()` で正しく列の値リストを取得
5. **条件検索**: 複雑な条件で正しく検索
6. **更新検知**: ファイル更新時、正しく検知して差分更新
7. **横断検索**: 複数テナントから正しく検索

### 性能テスト（中規模: 50テナント、各50ファイル）

- 初回ロード（1テナント）: <3秒
- 遅延ロード（1テナント）: <3秒
- 列単位検索: <50ms（インメモリ）
- 行単位検索: <50ms（インメモリ）
- 横断検索（10テナント）: <500ms
- メモリ使用（1テナント）: <50MB
- メモリ使用（50テナント全ロード時）: <2.5GB（運用では数十テナント同時アクセス想定）

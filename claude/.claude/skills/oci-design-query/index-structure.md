# インデックス構造

## 役割分担

**重要**: インデックスは**「どこにあるか」を示すポインタ情報のみ**を含み、実際のデータは含めない。

### 理由

- データの重複を避ける（インデックスとDataFrameで二重管理しない）
- インデックスは軽量に保つ（ファイル更新時の再構築コストを低減）
- 実際のデータはDataFrameから取得する（柔軟なクエリが可能）

## by_resourceインデックス（主キー検索用）

### 目的

「特定リソースの全属性値」を高速に取得するための位置情報

### 構造

```
{テナントID} → {リソースタイプ} → {主キー値} → {
  "sheet": "シート名",
  "row": 行番号,
  "primary_key": 主キーの値
}
```

### 例

```json
{
  "ocicloudjapanuser1": {
    "VCN": {
      "ai-vcn": {
        "sheet": "VCN",
        "row": 3,
        "primary_key": "ai-vcn"
      }
    }
  }
}
```

### 問い合わせフロー

1. `get_row("ocicloudjapanuser1", "VCN", "ai-vcn")` が呼ばれる
2. インデックスから `{"sheet": "VCN", "row": 3}` を取得
3. DataFrameの`df.iloc[3]` で行データを取得
4. 辞書形式で返す

### 計算量

O(1)

## by_column_valuesインデックス（逆引き検索用）

### 目的

「ある列の全設定値リスト」を高速に取得するための逆引き

### 構造

```
{テナントID} → {カラム名} → {値} → [(リソースタイプ, 主キー値), ...]
```

### 例

```json
{
  "ocicloudjapanuser1": {
    "環境": {
      "ルート": [
        ("VCN", "ai-vcn"),
        ("VCN", "web-vcn"),
        ("Instance", "ubuntu_server")
      ],
      "sandbox": [
        ("VCN", "sandbox-vcn-1")
      ]
    },
    "コンパートメント名": {
      "ai-cmp": [
        ("VCN", "ai-vcn"),
        ("Instance", "ubuntu_server")
      ],
      "sandbox": [
        ("VCN", "sandbox-vcn-1")
      ]
    }
  }
}
```

### 問い合わせフロー

1. `get_column_values("ocicloudjapanuser1", "環境")` が呼ばれる
2. インデックスから値ごとのリソースリストを取得
3. 必要に応じてDataFrameから詳細データを取得
4. 集約して返す

### 計算量

O(1)

## DataFrameキャッシュとの連携

### DataFrameの役割

- 実際のデータを保持
- インデックスで特定された位置から行データを取得
- 柔軟なクエリ（フィルタリング、集約など）が可能

### メモリ管理

- テナント単位で遅延ロード（初回アクセス時にのみロード）
- 50テナント×50ファイル=2,500ファイルあっても、同時アクセスは数十テナント想定
- 各テナント50MB程度と仮定すると、数十テナントで数GB（許容範囲）

### 構造

```
{テナントID} → {シート名} → pandas.DataFrame
```

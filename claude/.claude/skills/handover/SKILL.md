# Handover（引継ぎ）スキル

compact による記憶の歪み・喪失を防ぎ、次の session で作業を**構造的・再現性をもって再開**するための引継ぎ書を管理する。

## 目的と設計思想

compact で真っ先に失われるのは「具体識別子・判断の理由・失敗の否定履歴・ユーザ叱咤・一時状態」である。よって本スキルは事実の羅列ではなく**「理由付き・具体値付き」の記録**を強制する。各要素は固定セクションで構造化し、将来的に他スキルの情報源として再利用可能にする。

## 配置構造

PJルート直下に `HANDOVER/` を作成し、タイムスタンプ1件ごとにディレクトリで囲む（PJルートの肥大を隠すため）。

```
<PJルート>/HANDOVER/
├── HANDOVER-202607111200/
│   ├── HANDOVER.md            ← 本体（必須・1ファイル）
│   ├── response-example.json  ← 参考資料（長大JSON等）
│   └── snippet-*.py           ← コード断片
└── HANDOVER-202607111500/
    └── HANDOVER.md
```

### タイムスタンプ採番ルール

- 形式: `YYYYMMDDHHMM`（**分**まで）。`date +%Y%m%d%H%M` で取得する。
- 同分に既存ディレクトリがある場合は `-2`, `-3` … と連番 suffix を付与する（並列 session 衝突回避）。
- 最新の判定は**タイムスタンプの辞書式順序**（＝時系列）。`ls -d HANDOVER/HANDOVER-* | sort | tail -1` で最新を取得する。
- INDEXファイルは作らない（辞書式ソートで運用する）。

### 参考資料の分離基準

HANDOVER.md 本体に書かないもの:

- 長大JSON/API応答 → `response-example.json` 等
- ログ全量 → `logs/`
- 長いコード断片 → `snippet-*.py`
- 図・スクショ → `assets/`

分離ファイルは HANDOVER.md の「§10 参考資料」から相対パスでリンクする。

## コマンド分岐

`/handover` ＋ 自然言語両対応。引数は緩いキーワード判定で以下に分岐する。

| 入力例 | モード | 動作 |
|---|---|---|
| `/handover`、`引継ぎ書をかけ`、`handover 書いて`、`save`/`write` | **作成(write)** | 新規タイムスタンプdir生成 → テンプレ埋込 → 機密レビュー |
| `/handover 作業を再開`、`引継ぎを読んで再開`、`resume`/`continue` | **再開(resume)** | 最新dir読込 → 要点再構成 → 作業継続 |
| `/handover 一覧`、`list` | **一覧(list)** | dir一覧を表示 |
| `/handover show <ts>` | **閲覧(show)** | 指定時点を表示 |

## 作成フロー（write）

1. **タイムスタンプ取得**: `date +%Y%m%d%H%M` を実行。
2. **衝突チェック & ディレクトリ作成**: 同名dirがあれば `-2` 連番にする。`mkdir -p HANDOVER/HANDOVER-<ts>` を実行。
3. **テンプレート埋込**: `./handover-template.md` を `HANDOVER/HANDOVER-<ts>/HANDOVER.md` にコピーし、各セクションを埋める。**空欄でも見出しは残す**（欠損が一目で分かるようにする）。
4. **記録の鉄則**: §3〜§8 の各項目に `理由:` を必ず付ける。事実のみの記述は禁止する（理由が消えると compact 後に再調査を誘発する）。
5. **参考資料の分離**: 長大情報は別ファイルに分離し、HANDOVER.md からリンクする。
6. **機密レビュー（必須ゲート）**: HANDOVER/ は Git 追跡するため、`./security-review-checklist.md` に従い**必ず**機密スキャンを実施する。レビューを通過するまでコミットしてはならない。
7. **完了報告**: 作成したdirパスと要点3行をユーザに提示する。

## 再開フロー（resume）

1. **最新dir特定**: `ls -d HANDOVER/HANDOVER-* | sort | tail -1` を実行。
   - HANDOVER/ が存在しない場合は「引継ぎ書が無い」と伝え、作成を促す。
2. **HANDOVER.md を読む**: **必ず全文を読む**（要点だけ拾うと compact 歪みと同じ事故が起きる）。
3. **要点を口頭で再構成**: ユーザに「前回はここまで・次はここから・注意点はこれ」を3〜5行で再提示してから着手する。
4. **§2 現在の状態 を検証**: 記録されたファイルパス・未コミット状態が現実と一致するか確認する（ズレていれば修正してから作業する）。
5. **§8 忌避すべき振舞 を遵守**しつつ作業を再開する。

## 機密レビュー（Git追跡の前提）

HANDOVER/ は **Git追跡対象**。公開・共有リポジトリへの漏出リスクがあるため、作成フローのステップ6で**必須**実施する。詳細は `./security-review-checklist.md`。

## 記録すべき内容（コーディング用途）

テンプレート `./handover-template.md` の各セクションが以下に対応する。

- 概要(TL;DR): タスクの現在地と次の一手
- 現在の状態: 触っているファイル(パス+行番号)・未コミット差分・実行中プロセス・環境差分
- 完了進捗(DONE) / 残件(TODO): 優先度順、依存関係付き
- 調査で判明した制約・仕様・情報源: 確証度と出典付き。**試してダメだった否定情報も記録**
- 重要なデータ型・構造: JSONスキーマ等、調査が面倒だった非構造化情報（長大なら別ファイル）
- 操作方法: 頻繁に間違える手順（起動コマンド・テスト手順等）
- 忌避すべき振舞(DO NOT): ユーザ指摘・叱咤。CLAUDE.md 準拠事項も含む
- 未解決の疑問・ブロッカー
- 参考資料リンク

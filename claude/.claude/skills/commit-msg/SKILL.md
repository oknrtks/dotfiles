# Gitコミットメッセージ自動生成

ステージ済みの変更内容を解析し、一貫性のある日本語コミットメッセージを生成します。

## メッセージフォーマット

```
[L<レベル>] <型>: <スコープ>: <内容>
```

**レベル:**
- **L1** - 軽微な修正（typo、フォーマット、空白削除）
- **L2** - 通常の機能追加・変更（デフォルト）
- **L3** - 破壊的変更・主要機能追加

**型:**
- **追加** - 新規ファイル・機能
- **変更** - 既存コードの修正
- **削除** - ファイル・機能の削除
- **修正** - バグfix
- **移動** - ファイルの移動・リネーム
- **文書** - ドキュメントのみ

## 処理フロー

1. **前提条件チェック**
   - `git rev-parse --is-inside-work-tree` でGitリポジトリ内か確認
   - `git diff --staged --quiet` でステージ済変更の存在確認

2. **変更情報の取得**
   - `git diff --staged --stat` で変更ファイル一覧と行数取得
   - `git diff --staged` で詳細な差分取得（必要に応じて）

3. **解析とメッセージ生成**
   - スコープ推論（ファイルパターンから）
   - レベル判定（変更規模ベース）
   - 型判定（変更種類ベース）

4. **ユーザー確認**
   - 生成されたメッセージを提示
   - 実行、編集、キャンセルを選択

5. **コミット実行**
   - 許可後に `git commit -m "<メッセージ>"` を実行

## 自動判定ルール

### スコープ抽出

- ルート直下のファイル → ファイル名（例: `README.md`）
- サブディレクトリ内のファイル → ディレクトリ名/（例: `config/`、`src/`）
- ドットで始まる設定ファイル → 拡張子除去（例: `.gitignore` → `gitignore`）
- 複数ディレクトリにまたがる変更 → 主要ディレクトリまたは`multiple`

### レベル判定

- **L1（軽微）**: 変更 < 10行、typo・空白・フォーマットのみ
- **L2（通常）**: 10行 ≤ 変更 < 100行、通常の機能追加・変更
- **L3（大規模）**: 変更 ≥ 100行、複数ファイルの大幅変更、破壊的変更

### 型判定

- 新規ファイル追加 → `追加`
- ファイルの削除 → `削除`
- ファイル移動・リネーム → `移動`
- ドキュメントのみの変更 → `文書`
- バグ修正（fix/bug/修正キーワード含む）→ `修正`
- その他 → `変更`

## エラー処理

- ステージされた変更がない → ユーザーに促し、スキル終了
- Gitリポジトリ外での実行 → エラーメッセージ表示、スキル終了
- バイナリファイルのみのステージング → 適切なメッセージを生成
- 50ファイルを超える大量変更 → スコープを集約
